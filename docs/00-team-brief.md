# Flame Atlas — одна сторінка для команди

**Челендж:** NASA Space Apps 2026, «Flame in Freefall».
**Дедлайн:** неділя 15 листопада, 23:59. **Подаємо о 21:00.**

## Що будуємо

Веб-дашборд, який з 24 досліджень NASA з горіння в невагомості робить інструмент для пожежної безпеки
місячних баз, роверів і станцій:

1. **Сценарій → ранжування.** Задаєш середовище (кисень, тиск, гравітація, потік, матеріали) і бачиш
   найрелевантніші дослідження й тести з поясненням.
2. **Єдина таблиця тестів.** 22 різнорідні таблиці NASA (близько 2 800 тестів) зведені до однієї схеми.
   Фільтри й експорт для тих, хто будує моделі.
3. **Карта прогалин.** Де даних достатньо, а де їх немає: наприклад, для атмосфери місячної бази.
4. **Картки й порівняння досліджень.** Мета, паливо, умови, датчики, висновки.
5. **Питання й відповіді з джерелами.**

Головне правило продукту: **жодного твердження без джерела.** Аудиторія — науковці.

## Як працюємо

- Один спільний контекст для всіх AI-агентів: `AGENTS.md`. Кожен агент спершу читає його і файл своєї ролі.
- Контракти даних (`docs/04-contracts.md`) і зразки (`data/fixtures`) є з першої хвилини, тому ніхто нікого не чекає.
- У кожної папки один власник. Чужу папку не правимо.
- Чотири контрольні точки: субота 18:30 і 23:00, неділя 13:00 (заморожуємо функції) і 17:00 (заморожуємо код).
- Заблокований довше 20 хвилин — пиши в чат.

BMAD і Spec Kit цілком не беремо: вони розраховані на послідовну роботу й забирають години на старт.
Беремо з них ідеї. Подробиці в `docs/06-working-agreement.md`.

## Ролі: оберіть свою

| Роль | Що робить | Кому підійде | Головний результат |
|---|---|---|---|
| **A — AI lead** | схема даних, зведення таблиць через LLM, картки досліджень, відповіді з джерелами, метрики якості | найбільше працював з LLM API і промптами | `tests.json`, `investigations.json`, `/api/ask` |
| **B — Data engineer** | завантаження з NASA PSI, розбір PDF, DOCX, XLSX, статті, пошуковий індекс, репозиторій, CI, деплой | любить API, скрипти й порядок | усе з PSI на диску, текст документів, робочий деплой |
| **C — Core і API** | ранжування, карта покриття, прогалини, порівняння, експорт, маршрути API, тести | любить чисту логіку й числа | `packages/core`, API |
| **D — Frontend** | усі екрани, графіки, зручність | найшвидше збирає інтерфейси на React | застосунок за публічним посиланням |
| **E — Предметник, якість, демо** | глосарій, сценарії з джерелами, ручна перевірка даних, контрольні точки, слайди, подання | уважний, добре читає й пише англійською, вміє презентувати; код не обов'язковий | перевірені дані, подання о 21:00 |

Детальний бриф кожної ролі зі стартовим промптом для агента: `roles/A…E`.

Роль E — не «менеджер». У команді немає фізика чи хіміка, тому E єдиний, хто ловить помилки LLM
до того, як їх побачить журі.

## Перші 45 хвилин

1. Кожен пише в чат, яку роль бере (якщо на роль двоє — домовляємось за хвилину).
2. Підтверджуємо рішення D1–D8 у `docs/decisions.md` (стек, LLM-ключ, хостинг, формат демо).
3. B створює репозиторій, кладе туди цей набір файлів, дає всім доступ.
4. B і D роблять каркас і перший деплой.
5. Кожен відкриває свого агента, дає йому стартовий промпт зі свого файла ролі й читає план, який той запропонує.
6. E перевіряє на сайті Space Apps, що всі п'ятеро в команді й на одному Local Event.

## Що вже відомо про дані

- API PSI відкритий, без логіну, ліцензія CC0. Готових наборів даних NASA не дала.
- 24 дослідження, 22 таблиці експериментів, близько 2 840 рядків. Колонки всіх таблиць уже описані
  в `docs/03-data-sources.md`.
- Таблиці дуже різні: різні одиниці (mmHg, atm, bar, мольні частки), діапазони й переліки в клітинках,
  текст замість чисел. Це головна технічна робота.
- У частини досліджень API не віддає список документів. Це перший ризик ролі B.
- Сирі дані (відео, до 2 ТБ на дослідження) не чіпаємо.
