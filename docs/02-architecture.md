# Архітектура

## 1. Потік даних

```
psi.nasa.gov ──ingest (B)──► data/raw/PSI-xx/        метадані, 22 CSV, документи
                                │
              parse (B) ────────┤──► data/interim/     текст документів посторінково
                                │
     normalize (A) ◄── CSV ─────┤──► data/processed/tests.json
     cards (A) ◄── метадані + текст ► data/processed/investigations.json
     enrich (B) ◄── DOI ────────────► publications у investigations.json
     index (B) ─────────────────────► sources.json, chunks.json, search-index.json
                                │
                packages/core (C)    rank, coverage, gaps, compare, export
                                │
                apps/web (D + C + A) сторінки, /api/*, /api/ask, /api/explain
                                │
                             Vercel  публічне посилання
```

Пайплайн запускається локально. Його результат (`data/processed/*.json`) комітиться в репозиторій,
і застосунок читає ці файли під час збірки. База даних не потрібна: даних мало
(24 картки, близько 2 800 тестів, кілька тисяч фрагментів тексту).

## 2. Де працює LLM

| Крок | Що робить LLM | Що робить код |
|---|---|---|
| Маппінг таблиць | для кожної з 22 таблиць пропонує `TableMapping`: колонка → поле, одиниця, перетворення | застосовує маппінг до всіх рядків, перераховує одиниці, перевіряє zod-схемою |
| Розбір рядків палива | унікальні значення на кшталт `100 micron PMMA film 2 cm wide` → матеріал, геометрія, розміри | кеш за значенням, підстановка в рядки |
| Картки | з метаданих PSI і тексту документів складає поля картки з джерелами й дослівними цитатами | шукає кожну цитату в тексті джерела; не знайшов — відкидає твердження |
| Пояснення ранжування | формулює, чому дослідження релевантне сценарію, з посиланням на картку й знайдені тести | рахує бал і складники; текст LLM бал не змінює |
| Ask | відповідає на питання за знайденими фрагментами з маркерами джерел | шукає фрагменти (BM25), перевіряє цитати, повертає `notFound`, якщо доказів немає |

Усі 24 картки (приблизно 12 тисяч токенів) кладемо в системний промпт `ask` і `explain` з кешуванням промпту.
Тому модель завжди бачить повну картину досліджень, а пошук потрібен лише для деталей з документів.

Офлайн-кроки кешують відповіді LLM на диску (`.cache/llm/<hash>.json`). Повторний запуск пайплайна
нічого не коштує і дає той самий результат.

## 3. Чому так

- **Маппінг на таблицю, а не LLM на рядок.** 22 виклики замість 2 800, результат відтворюваний,
  помилку видно в одному JSON-файлі й легко виправити вручну.
- **Детерміноване ранжування.** Науковець має бачити, з чого складається бал. LLM, який «оцінює
  релевантність», дає різні відповіді на той самий запит.
- **BM25 замість embeddings.** Корпус малий, терміни специфічні (назви палив, абревіатури). MiniSearch
  працює в Node без ключів і моделей. Embeddings додамо, лише якщо лишиться час.
- **Один застосунок Next.js.** Один деплой, одне публічне посилання, ключ LLM лишається на сервері.

## 5. Формула ранжування (v0)

Бал дослідження для сценарію: `score = 100 × Σ wᵢ · sᵢ`.

| Складник | Як рахуємо | Вага |
|---|---|---|
| `o2` | 1, якщо O₂ сценарію в діапазоні тестів дослідження; інакше `exp(−(d/8)²)`, де d — відстань у відсоткових пунктах | 0.25 |
| `fuel` | 1, якщо стан палива збігається; 0.5 для визнаного аналога (газовий пальник BRE імітує тверді матеріали); 0 інакше | 0.20 |
| `pressure` | як `o2`, з масштабом 25 кПа | 0.15 |
| `pillar` | 1 для основного напряму; 0.6 для додаткового; 0.2 інакше; 1, якщо фокус `all` | 0.15 |
| `flow` | як `o2`, з масштабом 15 см/с | 0.10 |
| `data` | багатство даних: логарифм кількості тестів, наявність таблиці, кількість статей | 0.10 |
| `gravity` | для 0 g: micro = 1; для Місяця й Марса: partial-simulated = 0.9, micro = 0.7, normal = 0.5 | 0.05 |

Якщо значення невідоме, складник дорівнює 0.5 і в `caveats` з'являється застереження.
Ваги лежать у конфігу. C і E калібрують їх на трьох демо-сценаріях і записують підсумок у `docs/decisions.md`.

## 6. Деплой і секрети

- Vercel-проєкт підключений до `main`; кожен пуш дає прев'ю.
- `LLM_API_KEY`, `LLM_MODEL`, `LLM_MODEL_FAST` задані в env Vercel і в локальному `.env.local`.
- `/api/ask` і `/api/explain` мають обмеження частоти запитів і ліміт довжини питання,
  бо посилання публічне.
- Пояснення для трьох демо-сценаріїв рахуємо заздалегідь і кладемо в `data/processed`,
  щоб демо не залежало від живого виклику.

## 7. Ризики

| Ризик | Що робимо |
|---|---|
| Порожній список файлів у частини досліджень | B шукає запит дерева файлів у першу годину; запасний шлях — ручне завантаження |
| LLM вигадує числа чи висновки | цитати перевіряє код; ручна вибірка E; `null` замість здогаду |
| Маппінг таблиці неправильний | E звіряє 40 записів з CSV; маппінг — це JSON, який виправляється вручну |
| Не встигаємо всі 22 таблиці | пріоритет з `docs/03-data-sources.md`; решта лишається в картках без тестів |
| LLM API недоступний на демо | static-first, заздалегідь пораховані пояснення |
| Конфлікти в git | власники папок, короткі гілки, контракти заморожені після контрольної точки 1 |
