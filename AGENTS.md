> Кожен агент читає цей файл на початку кожної сесії (`CLAUDE.md` його імпортує).
> Після нього агент читає файл своєї ролі з `roles/` і `docs/04-contracts.md`.

## 1. Що ми будуємо

**Flame Atlas** (робоча назва) — веб-дашборд для челенджу NASA Space Apps 2026
«Flame in Freefall: SI-Powered Fire Safety Insights from Microgravity Combustion Data».

Дашборд підсумовує, ранжує й тлумачить 24 дослідження з горіння з бази NASA PSI
(psi.nasa.gov) для пожежної безпеки кораблів, станцій, місячних і марсіанських баз,
герметичних роверів. Користувач:

1. задає середовище (кисень, тиск, гравітація, потік повітря, матеріали) і отримує
   ранжований список найрелевантніших досліджень і тестів з поясненням;
2. фільтрує й експортує єдину таблицю тестів (дані для прогнозного моделювання);
3. бачить, які дослідження стосуються запобігання, виявлення й гасіння пожеж,
   порівнює їх і бачить прогалини в даних;
4. ставить питання й отримує відповідь із посиланнями на джерела.

Аудиторія: професори, аспіранти, студенти, аерокосмічні інженери. Вони пробачать
простий інтерфейс, але не пробачать неправильне число.

Дедлайн подання: **неділя 15 листопада 2026, 23:59 за київським часом**.

## 2. Незмінні принципи

1. **Жодного твердження без джерела.** Кожен факт у картці, поясненні чи відповіді
   має `citations` з документом і місцем у ньому. Немає джерела — немає твердження.
2. **`null` краще за здогад.** Якщо значення не знайдено в джерелі, поле лишається `null`.
   Модель нічого не дофантазовує з «загальних знань про горіння».
3. **LLM пише маппінг, код його застосовує.** Нормалізація таблиць — це специфікація
   маппінгу на таблицю (JSON) плюс детермінований код. LLM не переписує рядки по одному.
4. **`raw` зберігається завжди.** Кожен нормалізований запис містить вихідні колонки без змін
   і номер рядка у вихідному файлі.
5. **Цитати перевіряються програмно.** Дослівна цитата з відповіді LLM має знайтися
   в тексті джерела. Не знайшлась — твердження відкидається.
6. **Ранжування детерміноване й пояснюване.** Бал рахує чиста функція з відкритими вагами.
   LLM лише формулює пояснення, але не виставляє бал.
7. **Контракти — єдине джерело правди.** Типи й формати файлів описані в
   `docs/04-contracts.md` і в `packages/contracts`. Змінювати їх може лише роль A після
   повідомлення в чат команди.
8. **Static-first.** Застосунок працює на готових JSON з `data/processed`. Живі виклики LLM
   потрібні лише для `/api/ask` і `/api/explain`. Якщо LLM недоступний, решта працює.
9. **Мінімум інфраструктури.** Без бази даних, авторизації, черг і мікросервісів.
10. **`main` завжди збирається.** Перед пушем: `pnpm typecheck && pnpm build`.
11. **Продукт англійською.** Інтерфейс, тексти, код, коментарі, коміти, README,
    слайди й текст подання — англійською. Внутрішні документи команди — українською.
12. **Сирі дані PSI не чіпаємо.** Папки `Raw Data` (відео, кадри, телеметрія, до 2 ТБ
    на дослідження) не завантажуємо. Беремо метадані, таблиці експериментів і документи.

## 3. Стек (рішення D1–D5 у `docs/decisions.md`)

- TypeScript усюди, Node ≥ 20, pnpm workspaces.
- Веб і API: Next.js (App Router), Tailwind, shadcn/ui, Recharts. Хостинг: Vercel.
- Пайплайн: Node-скрипти (`tsx`) у `pipeline/`. Результат — JSON у `data/processed`.
- Схеми: zod у `packages/contracts`. Тести: vitest.
- Пошук: MiniSearch (BM25) по фрагментах документів. Embeddings — лише як бонус.
- LLM: офіційний SDK провайдера, модель з env `LLM_MODEL` (типово `claude-opus-5-5`),
  для дешевих масових викликів `LLM_MODEL_FAST` (типово `claude-haiku-5-5`).
  Ключ лежить тільки в `.env.local` і в env Vercel, у репозиторій не потрапляє.
  Сигнатури SDK не вгадуй з пам'яті: звіряй з документацією провайдера.

## 4. Структура репозиторію та власники

Кожна папка має одного власника. У чужій папці агент нічого не змінює: він пише
власнику або відкриває окремий PR з позначкою ролі.

| Шлях | Власник | Що там |
|---|---|---|
| `packages/contracts/` | A | zod-схеми й типи з `docs/04-contracts.md` |
| `pipeline/src/ingest/`, `parse/`, `enrich/`, `index/` | B | завантаження з PSI, розбір документів, статті, пошуковий індекс |
| `pipeline/src/normalize/`, `cards/`, `llm/`, `eval/` | A | маппінги таблиць, картки досліджень, обгортка LLM, оцінка якості |
| `packages/core/` | C | ранжування, покриття, прогалини, фільтри, експорт (чисті функції) |
| `apps/web/app/api/` | C (крім `ask`, `explain`) | маршрути API |
| `apps/web/app/api/ask/`, `explain/`, `apps/web/lib/ask/` | A | відповіді з джерелами, пояснення ранжування |
| `apps/web/app/` (сторінки), `apps/web/components/` | D | інтерфейс |
| `data/raw/`, `data/interim/` | B | завантажене з PSI і розібраний текст |
| `data/processed/` | пише пайплайн (A, B) | файли, які читає застосунок |
| `data/fixtures/` | A | зразки за контрактами для старту без даних |
| `data/review/`, `submission/`, `docs/07-glossary.md` | E | перевірка даних, сценарії, демо, подання |
| CI, деплой, кореневі конфіги | B | Vercel, GitHub Actions, workspace |

## 5. Цільові команди

Їх створюють B і A у першу годину. Якщо команди ще немає, агент створює її у своїй зоні.

```
pnpm install
pnpm dev                 # веб на localhost:3000
pnpm typecheck && pnpm build
pnpm test                # vitest
pnpm pipeline:ingest     # PSI -> data/raw
pnpm pipeline:parse      # документи -> data/interim
pnpm pipeline:normalize  # таблиці -> data/processed/tests.json
pnpm pipeline:cards      # картки -> data/processed/investigations.json
pnpm pipeline:index      # chunks.json, sources.json, search-index.json
pnpm data:check          # zod-перевірка всіх файлів data/processed
pnpm eval                # метрики якості -> data/processed/eval.json
```

## 6. Правила роботи агента

- Спершу прочитай: цей файл, файл своєї ролі, `docs/04-contracts.md`. Для задач з даними
  ще `docs/03-data-sources.md`, для термінів `docs/07-glossary.md`.
- Задача довша за 30 хвилин починається з короткого плану (режим планування). Менші роби одразу.
- Одна задача — одна гілка `<роль>/<короткий-опис>` (наприклад `c/rank-v0`), живе до 2 годин,
  зливається в `main` малими комітами. Повідомлення комітів англійською.
- Працюй проти фікстур з `data/fixtures`, доки немає справжніх даних. Формати однакові.
- Виклики LLM кешуй на диску за хешем запиту (`.cache/llm/`), щоб повторний запуск був безплатним.
- Потрібна зміна контракту — не міняй сам. Опиши зміну одним абзацом для чату команди.
- Не додавай залежностей без потреби. Велика нова залежність — рішення в `docs/decisions.md`.
- Кожне рішення, яке впливає на інших, запиши одним рядком у `docs/decisions.md`.
- Коротко запиши в `docs/si-usage-log.md`, що зроблено з допомогою AI: це обов'язкове поле подання.
- Усі зовнішні джерела (код, бібліотеки, дані, зображення) додавай у `submission/references.md`.
- Застряг більше ніж на 20 хвилин — зупинись і сформулюй питання для чату команди.

## 7. Доменний мінімум

- У невагомості немає плавучості, гарячі гази не піднімаються. Полум'я живе на дифузії
  кисню й потоці вентиляції, тому слабкий потік може підтримувати горіння, а не гасити.
- Три напрями пожежної безпеки: **prevention** (що й за яких умов горить),
  **detection** (дим, датчики), **suppression** (гасіння, межі згасання).
  Четвертий тег **fundamentals** — фундаментальні досліди, які прямо не лягають у ці три.
- Головні параметри умов: частка кисню (% об.), тиск, швидкість і напрям потоку,
  тип і геометрія палива, гравітація.
- Ключовий сценарій челенджу: бази й ровери з ≥30% O₂ і тиском ≤10.2 psi (≤70.3 кПа).
  Скафандр: 100% O₂ при 4.3 psi (29.6 кПа). Земля: ~21% O₂, 14.7 psi (101.3 кПа).
- Даних про часткову гравітацію в PSI немає. E-FIELD Flames її імітує електричним полем.
- Перерахунок: 1 psi = 6.894757 кПа, 1 atm = 101.325 кПа, 1 mmHg = 0.133322 кПа,
  1 bar = 100 кПа, мольна частка × 100 = % об.

## 8. Чого не робити

- Не робити власних фізичних висновків і не «покращувати» висновки авторів.
- Не будувати модель горіння без підтвердження від ролі E, що колонки означають те, що ми думаємо.
- Не писати ракетну тематику й паливо для двигунів: це поза межами челенджу.
- Не комітити ключі, файли понад 50 МБ і папку `.cache/`.
- Не переписувати чужий код «заодно».
