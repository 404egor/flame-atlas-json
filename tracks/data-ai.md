# Команда «Дані й AI» — список задач (3 людини)

**Мета команди:** перетворити різнорідні таблиці NASA PSI на перевірені дані в одному форматі.

**Що віддаємо команді «Продукт»:** чотири файли в `data/processed` за контрактом з
[contracts/README.md](../contracts/README.md): `tests.json`, `investigations.json`, `scenarios.json`, `meta.json`.

**Наші папки:** `pipeline/`, `data/`, `contracts/`, `docs/07-glossary.md`, `submission/`.

**Стек:** Python 3.11+, pandas. Результат комітимо як JSON.

**Перед роботою прочитай:** `AGENTS.md`, `contracts/README.md`, `docs/03-data-sources.md`.

**AI в нашій роботі.** LLM допомагає наперед у трьох місцях: пропонує маппінг таблиці, розбирає назви
матеріалів, пише тексти карток. Працювати можна через AI-агента для коду або через API.
Кожен результат перевіряє код і людина. На сайті LLM поки не викликається.

Позначки: `одна людина`, `пара`, `порівну`. Задачі **КШ** лежать на критичному шляху: їх беремо першими.
Три умовні місця в команді: **AI**, **Пайплайн**, **Предметник**. Люди можуть мінятись задачами.

Кроки йдуть по порядку. Усередині кроку задачі виконуються паралельно.
Команда «Продукт» у цей самий час іде своїми кроками з тими самими номерами.

## Крок 1. Пілот наскрізь

### DA-4. Завантаження: метадані й 22 таблиці — `одна людина` (Пайплайн) — **КШ**
- Запити й поля описані в `docs/03-data-sources.md`. Кеш на диску, пауза між запитами.
- Список досліджень → фільтр Combustion Science → 24 ID. Деталі кожного → `data/raw/PSI-xx/metadata.json`.
- Для кожної таблиці експериментів: посилання (`redirect=false`) → CSV у `data/raw/PSI-xx/tables/`.
  CSV читати з `encoding="utf-8-sig"`.
- Тим самим способом завантажити малі файли ReadMe з папки `Science Documents`: це словники колонок.
- Звірити кількість рядків з `docs/03-data-sources.md` (разом 2 870). CSV і метадані закомітити.

**Готово, коли:** на диску 24 `metadata.json` і 22 CSV; повторний запуск нічого не качає.
**Розблоковує:** DA-5, DA-6, DA-10.

### DA-5. Рушій зведення таблиць — `пара` — **КШ**
- На вході CSV (читати як рядки, без автозаміни порожніх значень) і маппінг таблиці
  `pipeline/mappings/<таблиця>.json`: колонка → поле контракту, перетворення, значення за замовчуванням.
- Перетворення, кожне з тестом:
  - число; величина з одиницею всередині (`0.61 mm`, `20 cm/s`, `1 atm`);
  - діапазон (`21.5 - 21.7`) → `Min` і `Max`; перелік (`21; 26.5; 40`) → `Min`, `Max`, `o2PctValues`;
  - наближення (`~ 22.1`) → `o2PctApprox: true`;
  - текст замість числа (`RAMPED`, `Insignificant`, `n/a`) → `null`, оригінал лишається в `raw`;
  - мольна частка → %; mmHg, atm, bar, psi → кПа; enum за словником; дата в ISO.
- Еталон: сім записів у `data/fixtures/tests.json`. Рушій має відтворити їх із вихідних рядків.

**Готово, коли:** тести рушія зелені; вихід проходить `contracts/validate.py`.

### DA-6. Три пілотні маппінги — `порівну`, по одній таблиці на людину — **КШ**

| Таблиця | Що в ній складного |
|---|---|
| BASS-II | швидкість потоку лежить у колонці `Air display` (см/с, за ReadMe); `Fan display` — це напруга вентилятора; наслідку тесту в таблиці немає |
| FLEX | тиск у mmHg, склад у мольних частках; колонки `O`, `N`, `CO` — це O₂, N₂, CO₂: звірити з ReadMe |
| SAFFIRE-II | одиниці в значеннях, текст замість чисел, окремі колонки для 1 g: їх не плутати з результатом у невагомості |

Кроки для кожної таблиці:
1. Прочитати ReadMe дослідження: там пояснено, що означає кожна колонка.
2. AI пропонує маппінг за заголовками, десятьма рядками, текстом ReadMe і правилами з `contracts/README.md`.
3. Автор читає маппінг очима й виправляє.
4. **Інша людина** звіряє 5 записів з CSV.

**Готово, коли:** `data/processed/tests.json` містить три таблиці й проходить перевірку.

### DA-10. Маппінги решти таблиць — `порівну` — **КШ**
Порядок: спершу таблиці окремих тестів, важливі для безпеки.

| Хто | Таблиці | Особливості |
|---|---|---|
| AI | CFI-G Normal, CFI-G Inverse, SPICE, Flame Design Normal, Flame Design Inverse, CFI, FLEX-2 | `XO2` — мольна частка; тиск у bar або atm; `SE` і `FT` → наслідок; `RAMPED` → `null`; FLEX-2 — рядки матриці умов |
| Предметник | SAFFIRE-I, SAFFIRE-III, SAME, SAME-R, BASS, DAFT, PSI-142 | у BASS і SAME умов атмосфери немає: лишати `null`; у SAFFIRE-I є рядки про відео, а не про тести |
| Пайплайн | ACME BRE, CLD Flame, E-FIELD Flames, s-Flame, SLICE | рядок = день тестів; кілька значень O₂ в клітинці; колонка `Notes` — виноски до всієї таблиці |

Після кожної таблиці друкувати: рядків на вході й виході, частка заповнених кисню, тиску, потоку.

**Готово, коли:** усі таблиці в `tests.json`; зведення надіслано в чат.
Якщо не встигаємо, відкладаємо SLICE, DAFT, PSI-142, CLD Flame.

### DA-11. Назви матеріалів — `одна людина` (AI)
- Зібрати унікальні значення колонок палива. AI розбирає кожне на матеріал, стан, форму, розміри.
- Результат у `pipeline/mappings/fuel-map.json`, його читає людина.

### DA-12. Тексти карток — `одна людина` (AI)
- На вході поля метаданих PSI: `objective`, `approach`, `hypothesis`, `researchImpacts`.
- LLM пише `summary`, `objectives`, `measurements`, `fireSafetyRelevance` з дослівними цитатами.
- Код шукає кожну цитату в тексті поля. Не знайшов — твердження відкидається.
- Напрями безпеки беруться з таблиці предметника, а не від LLM.

**Готово, коли:** 24 картки проходять перевірку; частку відкинутих тверджень записано.

### DA-13. Перша ручна перевірка — `одна людина` (Предметник), допомагає той, хто звільнився
- 40 значень: по кілька записів з кожної великої таблиці. Поля: паливо, кисень, тиск, потік, наслідок.
- Результат у `data/review/qa-tests.csv`, підсумок у `meta.json` (`quality`).

**Як перевіряти, не будучи фізиком.** Ти перевіряєш, чи наше значення збігається з джерелом: те саме число,
та сама одиниця. Підозрілі ознаки: кругле число там, де в джерелі діапазон; одиниця змінилась без перерахунку.
